# Windows版の導入と復旧

[English](INSTALL.md)

[GitHub Releases](https://github.com/inuchanbt/km003c-fw-extensions/releases)から **Windows x64 ZIP** と `.sha256` を取得してください。GitHubが自動で付けるSource codeではなく、Windows用ZIPを使います。対象は **KM003C HW 2.3／既知の純正FW 2.0.7** です。[対応情報](../firmware/v2.0.7/profile.json)にあるアプリとloaderのハッシュまで一致する必要があり、別HW・別ビルド・不明な改変状態は拒否します。QRとキャプチャは別々に導入する版です。

## 準備

64bit WindowsとWindows PowerShell 5.1（Windows 10／11）を使用します。取得後の操作にPython・Rust・コンパイラー・ネット接続は不要です。ZIP全体をローカルフォルダへ展開し、ZIP内から直接実行しないでください。`Get-FileHash <ZIPのパス> -Algorithm SHA256` で添付のチェックサムと照合できます。実行ファイルは未署名です。チェックサムは内容の一致を確認するもので、コード署名ではありません。

本体は1台だけ接続し、**測定用の両コネクターは空にして、側面HIDだけをPCへ接続**します。ChargerLABアプリなど、本体を使う別ソフトは閉じてください。バックアップ・BOOT Loader確認・導入・復旧には、同じPCの同じ物理USBポートを使用します。このキットはUSBドライバーを追加・交換しません。本体確認で開けない場合は先にアクセス・ドライバーの問題を解決してください。[固定版のUSB実装](https://github.com/okhsunrog/km003c-rs/tree/efed50556d7376914bffd510e012aaa98081936f)も参照できます。

**Install.cmdをダブルクリック**し、英語または日本語を選びます。起動時に配布ファイルの一覧とハッシュを確認します。FWのダウンロードや書込みの自動開始はしません。

## 初回は 2 → 3 → 4 → 5

1. **2：初回の純正バックアップ。** 未改変の純正FWを、ボタンを押さずに通常起動します。表示されたシリアル番号を入力してください。アプリ・loader・内部末尾・校正値・外部NOR先頭3MiBを2回ずつ読み、内容を照合します。不一致・未完了のバックアップは使えません。保存先は展開フォルダの外、`%LOCALAPPDATA%\KM003C-FW-Extensions\`です。
2. **3：BOOT Loaderで復旧用の読取確認。** 上のバックアップを選択します。側面HIDを抜き、**Exitだけ**を押しながら**同じPC側USBポート**へ再接続。BOOT Loaderが出たら離し、Enterを押します。loaderとアプリを各2回読み、純正バックアップと照合します。フラッシュ書込みは行わず、BOOT Loaderに留まります。Exit＋OKは撮影操作ではありません。
3. **4：オフライン準備。** QRまたはキャプチャを選びます。純正／loaderの既知ハッシュ、バックアップの復旧確認、内部拡張領域の空白、選択した拡張データの固定ハッシュを確認し、**自分の本体のバックアップから**導入用bundleと2段階の純正復旧データを作ります。USB通信はしません。導入前に`stock-*`と`prepared-*`フォルダ全体を別の安全な場所にもコピーしてください。他人のバックアップで代用しないでください。
4. **5：導入。** バックアップと、作成された`bundle`サブフォルダを選びます。初回は旧bundleの質問を空欄で進めます。案内に従ってBOOT Loaderへ入り、**INSTALL**と入力してください。実機のHW・物理ポート・取得可能な識別情報・loader全体・内部全領域を照合し、範囲を限定して書き込み、全体を読み戻して確認します。その成功後、別の確認処理を経て拡張を起動し、通常モードで内部領域・校正値を再確認します。失敗した段階で停止し、自動再試行しません。

通常起動への再接続は**ボタンを押さず**に行います。QRは左右を約1秒同時押し。キャプチャは左右を0.5〜2秒未満押して離すと240×240、2秒以上では対応ページの縦長撮影です。[キャプチャ操作](SCREEN-CAPTURE-207.ja.md)、[QR操作](NATIVE-INFO-207.ja.md)を参照してください。

## 拡張の入れ替え

最初の純正バックアップを使い、4で別の版を準備します。5の質問で、**いま本体に入っている旧版のbundle**を明示してください。新旧のbundleを同じバックアップで監査し、実機が純正・今回の版・明示された旧版のいずれかと完全一致する場合だけ進みます。不明なFWを上書きする許可にはなりません。元のバックアップと各版のbundleを保管してください。

対応する外部保存版同士では画像を保持できますが、版の入れ替え・旧版への変更・復元の前に画像をPCへ取り出してください。旧方式の内部保存画像が`0x78000〜0x7C000`にある場合は、その版の操作で明示的に消去してから更新します。残っていれば保護領域の照合で停止します。追加バンクを知らない旧版へ戻す前には、現在のキャプチャ版で**両バンク**を取り出し・消去してください。

## 純正への復元・復旧

**6**で同じバックアップと対応するbundleを選び、Exitによる物理操作でBOOT Loaderに入ってから**RESTORE**と入力します。loader・保護領域を照合し、拡張部分を消すパスを適用・読み戻しした後、元のアプリを適用・読み戻しします。成功後にだけ純正を起動します。認識できる完了段階からの再開に対応しますが、不確かな転送をそのまま再送しません。

通信失敗や状態が不明な場合は停止し、記録を残してください。次の実機操作の前に側面HIDを抜き、Exitを押しながら再接続してBOOT Loaderへ入り直します。loaderがデータを待っている可能性があるため、別のボタン操作や転送の連打を避けてください。loader・保護領域・バックアップの不一致を拒否された場合は、回避せずファイルを保管して原因を確認します。初回の`dfu-recovery-check`が未完了なら復旧確認済みとは扱えません。未改変の純正へ通常起動し、新しいバックアップからやり直してください。

内部FWの復元は、外部画像の自動消去・転用済みDOOMデータの復元・任意の外部領域変更の復旧を行いません。初回バックアップが読む外部領域は先頭3MiBで、本体全体ではありません。キャプチャ版は未知のNORバンクを起動時に消去せず、既知の旧DOOMデータを転用する場合も本体上の2段階確認が必要です。[保存領域の境界](SCREEN-CAPTURE-207.ja.md)を参照してください。

## 配布内容と確認範囲

ZIPに含むのはWindows用ツール2本・起動メニュー・QR／キャプチャ別の拡張データ・英日手順・ライセンス・ファイル別SHA-256です。**純正アプリ・loader・更新コンテナー・校正値・個体識別情報・撮影画像は含みません。** 操作時に作られる`stock-*`、`prepared-*`、読取記録は非公開データです。不具合報告やGitHubへアップロードしないでください。

FW本体と範囲を限定した転送・復旧処理には、既知の本体1台での従来の実機確認があります。今回のメニューとネイティブ準備処理は、Windows上で非公開バックアップからの生成・候補全体の比較・復旧データの往復照合・展開後ZIPの動作・改変拒否をオフライン確認します。この新メニューを通した新規の実機書込みは今回行っていません。[Windows配布版の検証](WINDOWS-RELEASE.md)を参照してください。

開発者向けの[ソースビルド](../README.ja.md)と[更新ツールの詳細](../native-host/README.ja.md)も利用できます。

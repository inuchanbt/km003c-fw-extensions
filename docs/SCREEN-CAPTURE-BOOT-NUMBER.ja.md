# 画面キャプチャの起動番号

純正FW 2.0.7向けキャプチャ版0.3.0の変更。HW 2.3の1台で限定的に実機確認済み。

新規画像の例は `0001_MEASUREMENT01.BMP`、同じ起動中の次の画像は `0001_MEASUREMENT02.BMP`、再起動後の撮影は `0002_...`。番号は最低4桁で、9999の次は10000となり、最大99999999まで扱う。末尾の画像連番は従来どおり全画面共通。旧画像は元の名前と内容を保つ。長いメニュー名はFAT長名の上限に収まるよう短縮する。

番号は保存成功した起動を識別する。撮影しなかった起動やUSB取り出しだけの起動では番号用の書き込みをしない。画像の全消去後は1に戻り、異なる消去サイクル間で一意ではない。接続機器を識別するものではない。

新しい記録は従来の画像圧縮の前に40バイトのKSN2メタデータを保存し、番号とその反転値は記録全体のCRCと最終コミットでも保護される。既存のKSN1メタデータより8バイト増える。既存のデータを移行・消去せず、既存ジャーナルの通常の空き領域へ保存する。保存された番号の最大値から次の番号を決める。番号が不正なKSN2記録、または番号上限を検出した場合は保存を拒否する。

旧版キャプチャFWはKSN2を解釈できない。**旧版へ戻す前に画像を取り出し、現行版で両画像保存領域を消去すること。** 不明な外部データの自動消去は行わない。対応バンクが無効な間、その中の画像は番号判定にも含まれない。

## 2026-11-18 HW 2.3 実機確認

先行ビルド（拡張SHA-256 `cf397d27…`）を1台へ書き込み、内部全域の読み戻し、起動後の校正値とGUIコールバックの一致を確認。旧画像1枚を退避したうえで、同一起動の通常画像2枚、次の起動の通常画像1枚、さらに次の起動のModules縦長画像1枚を撮影した。USB経由で `0001_MEASUREMENT02.BMP`、`0001_MEASUREMENT03.BMP`、`0002_MEASUREMENT04.BMP` と `0003_MODULES05.BMP` を取得し、後者は240×283と確認。以前の `CAPACITY01.BMP` を含む全画像は繰り返し読んで一致した。縦長撮影後のスクロール位置復帰は所有者が確認した。

画面名を取得できない場合の `SCREEN` 表示を修正した公開用ビルド（`88a5d5e2…`）も同じ実機に更新し、全内部領域の読み戻し・起動後の校正値とGUIコールバックを照合。通常画面を1枚保存し、USBから `0004_MEASUREMENT06.BMP` を取得できた。先の5枚も一致し、通常画面への復帰後、内部全域と校正値の再照合も通った。画面名なしの分岐自体はPC試験で検証した。

ホスト側のテスト、実際のARMコードを使う画面描画・NORモデル試験、起動番号切り替えモデル、USBモデル試験も実施した。物理的な電源断、メモリー使用量の最大値、HW 2.1への書き込み・実機動作は未検証。完成した0.3.0のWindows ZIPを用いた実機導入は未実施で、オフライン検証と区別する。
